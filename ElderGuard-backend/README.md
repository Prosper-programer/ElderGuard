# ElderGuard Backend API

**ElderGuard** is an intelligent elderly monitoring and care assistance backend system built with **Node.js**, **Express**, **TypeScript**, and **MySQL**.

The backend serves as the centralized REST API communicating with MySQL and handles authentication, profile management, care activities, reminders, real-time IoT wearable telemetry, automated emergency alerts, GPS tracking, geofence breach detection, and administrative user controls.

---

## 1. Technology Stack

- **Runtime:** Node.js (v24+)
- **Framework:** Express.js (v4)
- **Language:** TypeScript
- **Database:** MySQL (v9.5) with direct connection pooling via `mysql2/promise`
- **Security & Authentication:** `bcrypt` (password hashing) + `jsonwebtoken` (JWT Bearer tokens)
- **CORS:** Cross-Origin Resource Sharing enabled

## 3. Database Schema (11 UML Tables)

The database schema directly maps to the **ElderGuard UML Class Diagram**:

| # | Table Name | UML Class | Purpose |
| :--- | :--- | :--- | :--- |
| 1 | `users` | `users` (`Parent`, `Caregiver`) | Stores user accounts with roles: `'parent'` or `'caregiver'`. |
| 2 | `admins` | `admin` | Stores dedicated administrative accounts. |
| 3 | `elderly_profiles` | `ElderlyPersonProfile` | Elderly profiles managed by Parents and assigned to Caregivers. |
| 4 | `daily_activities` | `DailyActivity` | Care routines and schedules (`pending` / `completed`). |
| 5 | `locations` | `Location` | GPS tracking data (`latitude`, `longitude`, `timestamp`). |
| 6 | `reminders` | `Reminder` | Medication, appointment, and health reminders. |
| 7 | `notifications` | `notification` | Notifications sent to users for reminders and alerts. |
| 8 | `alerts` | `Alert` | Emergency events triggered by IoT vitals or geofence breaches. |
| 9 | `iot_devices` | `IOT device` | Wearable monitoring devices paired to elderly profiles. |
| 10 | `geofences` | `Geofence` | Safe boundaries defined by a center GPS and radius (meters). |
| 11 | `reports` | `report` | Summary health and activity reports generated by Parents. |

## 5. API Endpoints Reference

### A. Health & Diagnostics
- `GET /` — Backend server health status.
- `GET /api/test-db` — Live MySQL connectivity check.

### B. Authentication (`/api/auth`)
- `POST /api/auth/register` — Register as `parent` or `caregiver`.
- `POST /api/auth/login` — Login as Parent or Caregiver (returns JWT).
- `POST /api/auth/admin-login` — Login as Administrator.
- `POST /api/auth/logout` — Stateless logout.
- `GET /api/auth/profile` — Get authenticated user details.

### C. Users (`/api/users`)
- `PUT /api/users/profile` — Update personal profile name and phone.
- `GET /api/users/caregivers` — List active caregivers available for assignment.

### D. Elderly Profiles (`/api/elderly`)
- `POST /api/elderly` *(Parent only)* — Create a new elderly profile.
- `GET /api/elderly` — List elderly profiles (managed or assigned).
- `GET /api/elderly/:id` — View full elderly profile and medical information.
- `PUT /api/elderly/:id` *(Parent only)* — Update elderly profile.
- `DELETE /api/elderly/:id` *(Parent only)* — Delete elderly profile.

### E. Daily Activities (`/api/activities`)
- `POST /api/activities` *(Parent only)* — Create an activity.
- `GET /api/activities/elderly/:elderlyId` — List activities for an elderly person.
- `GET /api/activities/statistics/:elderlyId` — Get completion rates and totals.
- `PATCH /api/activities/:id/record` — Record activity completion (`pending` / `completed`).
- `PUT /api/activities/:id` *(Parent only)* — Update activity.
- `DELETE /api/activities/:id` *(Parent only)* — Delete activity.

### F. Reminders (`/api/reminders`)
- `POST /api/reminders` *(Parent only)* — Create reminder (auto-triggers notification).
- `GET /api/reminders/elderly/:elderlyId` — View scheduled reminders.
- `PUT /api/reminders/:id` *(Parent only)* — Update reminder.
- `DELETE /api/reminders/:id` *(Parent only)* — Delete reminder.

### G. Notifications (`/api/notifications`)
- `GET /api/notifications` — Retrieve notifications for authenticated user.
- `GET /api/notifications/:id` — View single notification.
- `PATCH /api/notifications/:id/read` — Mark notification as read.

### H. IoT Wearable & Telemetry (`/api/iot`)
- `POST /api/iot/register` *(Parent only)* — Register wearable device.
- `POST /api/iot/:deviceId/connect` — Device connects to backend.
- `POST /api/iot/:deviceId/disconnect` — Device disconnects.
- `POST /api/iot/data` — Process incoming vitals (heart rate, SpO2, temp, fall detection). Automatically triggers alerts and notifications if abnormal.
- `GET /api/iot/devices` — List paired devices.

### I. Alerts (`/api/alerts`)
- `GET /api/alerts/elderly/:elderlyId` — List alerts for an elderly person.
- `GET /api/alerts/:id` — View single alert details.
- `POST /api/alerts` — Send manual emergency alert.

### J. Location & Geofence (`/api/locations` & `/api/geofences`)
- `POST /api/locations` — Submit GPS coordinate (automatically checks geofence).
- `GET /api/locations/current/:elderlyId` — Retrieve latest GPS fix.
- `GET /api/locations/history/:elderlyId` — GPS location breadcrumbs.
- `POST /api/locations/distance` — Calculate distance between two GPS coordinates using Haversine formula.
- `POST /api/geofences` *(Parent only)* — Set safe zone center and radius.
- `GET /api/geofences/:elderlyId` — View geofence configuration.
- `PATCH /api/geofences/:elderlyId/enable` *(Parent only)* — Enable geofence monitoring.
- `PATCH /api/geofences/:elderlyId/disable` *(Parent only)* — Disable geofence.
- `POST /api/geofences/:elderlyId/check-boundary` — Check if GPS point is within boundary.

### K. Reports (`/api/reports`)
- `POST /api/reports/generate` *(Parent only)* — Generate daily/weekly/monthly report.
- `GET /api/reports/elderly/:elderlyId` — View reports list.
- `GET /api/reports/:id` — View detailed report content.
- `GET /api/reports/:id/download` — Download report as text file.

### L. Admin (`/api/admin`)
- `GET /api/admin/users` *(Admin only)* — View all user accounts.
- `PUT /api/admin/users/:id/activate` *(Admin only)* — Activate an account.
- `PUT /api/admin/users/:id/deactivate` *(Admin only)* — Deactivate an account.
- `GET /api/admin/system-stats` *(Admin only)* — Platform overview statistics.

## 6. How to Run the Backend

### Quick start with Docker

Requirements: Docker Desktop with Compose enabled.

From this directory, start MySQL, initialize the schema, and launch the API with:

```bash
docker compose up --build
```

The API is then available at `http://localhost:5000` and the health check is `http://localhost:5000/`.
MySQL is exposed on `localhost:3307` to avoid conflicts with an existing local MySQL server.
The database data is persisted in the `mysql_data` Docker volume. The default development credentials are
`elderguard` / `elderguard_dev_password`; override them in a local `.env` file if needed.

To stop the services:

```bash
docker compose down
```

To stop them and delete the database volume:

```bash
docker compose down -v
```

### 1. Install Dependencies
```bash
npm install
```

### 2. Configure Environment (`.env`)
```env
PORT=5000
NODE_ENV=development

DB_HOST=localhost
DB_USER=root
DB_PASSWORD=YOUR_PASSWORD
DB_NAME=elderguard
DB_PORT=3306

JWT_SECRET=elderguard_super_secret_jwt_key_2026
JWT_EXPIRES_IN=7d
```

### 3. Initialize Database & Seed Tables
```bash
npm run db:init
```

### 4. Start Development Server
```bash
npm run dev
```
The server will start on: **`http://localhost:5000`**.
